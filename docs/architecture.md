# 全体設計

## コンセプト
**「AI時代のエンジニアキャリア」専門エージェント**
Webエンジニア・Web→AI移行層・AI/MLエンジニアを対象に、1人＋技術顧問で運営する。
自動化の目的は「面談の件数を増やすこと」ではなく、**面談枠を確度の高い候補者で埋めること**と、**事務作業をゼロに近づけること**。

## 全体像

```
┌──────── 候補者集客 ────────┐   ┌──────── 法人開拓 ────────┐
│ LP / 年収・スキル診断 (S2)  │   │ 企業シグナル収集 (S4)     │
│ LINE ナーチャリング (S2-3)  │   │ 企業スコアリング (S4)     │
│ 記事作成パイプライン (S3)   │   │ 営業シーケンス (S4)       │
│ スカウト文案の生成 (S5)     │   │ 求人票の構造化 (S5)       │
└─────────────┬─────────────┘   └─────────────┬────────────┘
              ▼                                ▼
     ┌──────────── Supabase (Postgres + pgvector) ────────────┐
     │ leads → candidates ─┐        companies → jobs          │
     │                     └──► applications ◄──┘             │
     │ outbound_messages（承認必須）  →  承認待ちキュー（人）  │
     │ マッチング候補の提示 (S5)  →  面談・推薦の判断（人）    │
     └─────────────────────┬──────────────────────────────────┘
                           ▼
     ┌──── バックオフィス (S6) ────┐
     │ placements → freee請求      │
     │ 返金期限の管理               │
     │ 法定帳簿・事業報告・情報公開 │
     │ KPIダッシュボード            │
     └─────────────────────────────┘
```

## スプリント計画

| # | 期間 | 内容 | 仕様書 |
|---|---|---|---|
| S1 | 1〜2週 | 基盤：認証、管理画面、カンバン、承認キュー、共通ライブラリ | `specs/S1-foundation.md` |
| S2 | 3〜4週 | LP、年収・スキル診断、LINE連携、リード管理 | `specs/S2-diagnosis-lp-line.md` |
| S3 | 5〜6週 | 記事作成パイプライン（キーワード → 構成 → 下書き → 顧問の監修 → 公開）、ナーチャリング配信、SNS予約投稿 | 未作成 |
| S4 | 7〜8週 | 企業シグナル収集（資金調達ニュース、採用ページ・ATSの求人数）、スコアリング、営業シーケンス、返信の自動分類 | 未作成 |
| S5 | 9〜10週 | 求人票の構造化、職務経歴書の解析、GitHub解析、embeddingマッチング、推薦文・スカウト文の下書き、面談議事録の要約 | 未作成 |
| S6 | 11〜12週 | 請求（freee）、返金期限のアラート、法定帳簿のCSV出力、事業報告、KPIダッシュボード | 未作成 |

## LLMの使い分け
- **構造化・分類**（求人票の構造化、返信分類、スキル抽出）：軽量・低コストのモデル
- **文章生成**（記事の下書き、営業メール、推薦文）：上位モデル
- モデル名は環境変数（`LLM_MODEL_FAST` / `LLM_MODEL_QUALITY`）で切り替え、コードに直書きしない
