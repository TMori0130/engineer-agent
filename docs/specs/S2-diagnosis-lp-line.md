許可が下りる前から**見込み候補者（リード）を集め始められる**状態にする。

- 公開サイトのトップ（LP）、プライバシーポリシー、会社概要

- LINE公式アカウントとの連携（友だち追加 → リード登録 → 診断結果の送付）

> 許可を取得するまでは「職業紹介」を行わない。LPの文言は「キャリア相談」「市場価値診断」にとどめ、許可番号の欄は取得後に掲載する。

## 1. LP（`/`）
- メッセージ：**「AI時代のエンジニアキャリア」**。Webエンジニア → AIを扱えるエンジニアへの移行を支援
- 構成：ヒーロー → 3つの強み（技術がわかる／AI領域に強い／押し売りしない）→ 技術顧問の紹介 → 診断へのCTA → FAQ
- 計測：GA4、UTMパラメータを `leads.utm` に保存する
- `src/app/(public)/` に配置する。SSG。OGP画像を設定する

## 2. 年収・スキル診断（`/diagnosis`）

### 入力（4ステップ、所要2分）
1. 職種（バックエンド / フロントエンド / フルスタック / SRE・インフラ / ML / データ / その他）
2. 経験年数、現在の年収帯
3. スキル（言語・FW・クラウド・AI関連）を複数選択。任意で GitHub ユーザー名
4. AIの活用度（使っていない / 業務でAIツールを利用 / LLMを組み込んだ開発経験 / MLモデルの開発・運用）

### 出力
- **推定市場年収レンジ**（例：650〜780万円）
- **セグメント判定**（`web` / `web_to_ai` / `ai_ml`）
- **年収を上げるための次のスキル**（3つ）
- 相性のよい企業タイプ（例：「シリーズB〜Cで、AI機能の開発を始めたSaaS企業」）

### 推定ロジック（`src/domain/diagnosis/`）
- **MVPではルールベース**にする（LLMは使わない）：職種 × 経験年数の基準表 ＋ スキル加点。基準表は `src/domain/diagnosis/salary-table.ts` に置き、出典とメモをコメントで残す。
- 将来：求人DBの `salary_min/max` が貯まったら、そこから基準表を再計算する（S6以降）。
- 「次のスキル」の文章だけは、テンプレートの組み合わせで生成する。
- **テスト必須**：代表的な入力パターン10件のスナップショットテスト。

### リード登録のフロー
```
入力完了
  → 結果の一部（年収レンジ）を表示
  → 詳細レポートを受け取るには「メール」または「LINE」で登録
      ├ 同意チェック（必須：プライバシーポリシー ／ 任意：情報提供メール・LINE）
      ├ leads に登録、consents に記録（policy_version、IP、UA）
      └ 詳細レポートを送付（transactional なので承認不要）
```
- 書き込みは Route Handler（`/api/leads`）から service_role で行う。レート制限と Cloudflare Turnstile を入れる。
- GitHub ユーザー名が入力された場合は、公開APIで公開リポジトリの言語構成とスター数だけを取得し、`diagnosis_input` に保存する（S2では表示のみ。解析はS5）。

## 3. LINE連携
- Messaging API の Webhook：`/api/line/webhook`（署名を検証する）
- **友だち追加（follow）**：`leads` を作成（`source = 'line'`）。あいさつメッセージ＋診断への導線（LIFF で `/diagnosis?via=line`）
- **LIFFで診断を完了**：LINEのユーザーIDとリードを紐付け、詳細レポートをLINEで送付
- **ブロック（unfollow）**：`leads.unsubscribed_at` を設定する
- **メッセージ受信**：`interactions` に保存し、管理画面に未読バッジを出す。自動返信は「担当者から返信します」の固定文のみ
- ステップ配信は S3 で実装する（ここではテーブル・テンプレートの準備のみ）

## 4. 管理画面への追加
- `/admin/leads`：一覧（流入元・セグメント・エンゲージメントスコア）、「候補者に昇格」ボタン（`candidates` を作成し、`leads.converted_candidate_id` を設定）
- ダッシュボードに「今週の新規リード数（流入元別）」を追加
