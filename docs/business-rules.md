# 事業・法務ルール

> ⚠️ 法令の数値・要件は改正されることがあります。本番運用の前に、最新の厚生労働省資料と社労士・弁護士で確認してください。
> このファイルは「システムが守るべきルール」をまとめたもので、法的助言ではありません。

## 1. 事業の前提

| 項目 | 内容 |
|---|---|
| 事業 | 有料職業紹介（厚生労働大臣の許可制） |
| 対象 | Webエンジニア / Web→AI移行層 / AI・MLエンジニア |
| 体制 | 代表1名（職業紹介責任者を兼ねる）＋技術顧問（副業の現役CTO・COO） |
| 人が担う業務 | 候補者面談、推薦の判断、選考調整、内定・入社のサポート |
| 自動化する業務 | 集客、法人開拓、文案の生成、事務、請求、法定帳簿・報告 |

## 2. セグメント定義（`segment` enum）

| 値 | 意味 | 典型 |
|---|---|---|
| `web` | Webエンジニア | バックエンド、フロントエンド、フルスタック、SRE |
| `web_to_ai` | Web→AI移行層 | LLMアプリ開発、AI機能を組み込むプロダクト開発 |
| `ai_ml` | AI・MLエンジニア | MLエンジニア、MLOps、データサイエンティスト、研究開発 |

## 3. 手数料・返金

- 手数料率の初期値は **理論年収の35%**。企業ごとに `companies.fee_rate` で上書きできる。
- 理論年収 = 月給 × 12 + 賞与（想定）＋ 固定残業代など。契約書の定義に従う。
- 返金規定の初期値（企業ごとに `companies.refund_policy` で上書きできる）：

| 入社からの退職時期 | 返金率 |
|---|---|
| 1ヶ月以内 | 80% |
| 1ヶ月超〜3ヶ月以内 | 50% |
| 3ヶ月超 | 返金なし |

- 計算ロジックは `src/domain/fee.ts` に純粋関数として実装し、テストする。

## 4. 法定対応（システムで自動化する対象）

| 対応 | システム上の実装 |
|---|---|
| 求人管理簿・求職管理簿の備え付け | `v_job_ledger` / `v_candidate_ledger` ビュー → CSV出力 |
| 職業紹介事業報告書（年1回） | `v_annual_report` ビュー |
| 情報公開（就職者数、6ヶ月以内の離職者数、手数料など） | `v_annual_report` ビュー → 公開ページに反映 |
| 個人情報の同意取得 | `consents` テーブル。同意文のバージョンを記録する |
| 求職者への金銭等による勧誘の禁止 | 該当する機能を実装しない（CLAUDE.md 絶対ルール4） |

## 5. 外部送信のルール

| 種類 | `kind` | 承認 | 例 |
|---|---|---|---|
| トランザクション | `transactional` | 不要 | 診断結果の送付、登録完了、日程確定の通知 |
| ナーチャリング | `nurture` | 必要（テンプレート単位で承認すれば可） | LINEステップ配信、メルマガ |
| 個別アウトリーチ | `outreach` | **1通ごとに必要** | 営業メール、スカウト文、候補者への求人提案 |

- テンプレート単位の承認：`message_templates.approved_at` が入っているテンプレートは、差し込みだけを行った配信なら個別の承認を不要とする。LLMで本文を個別に生成した場合は `outreach` 扱い。
- 営業メールのフッター：送信者名、所在地、連絡先、配信停止リンク。

## 6. 技術顧問との関係

- 顧問料は**固定報酬**とする。候補者の紹介に連動した成果報酬は払わない（無許可の職業紹介と見なされるリスクがあるため。変更する場合は社労士に確認する）。
- 顧問のシステム権限は `staff.role = 'advisor'`。候補者の連絡先（メール・電話・LINE）は閲覧できない。

## 7. データ保持

- 候補者から削除の依頼があったら、30日以内に論理削除＋PIIの匿名化を行う（`deleted_at` を設定し、PII列を NULL にする）。
- 法定帳簿に必要な最小限の情報は、法定の保存期間のあいだ保持する（期間は確認のうえ `docs/` に追記する）。
